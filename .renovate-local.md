# Renovate merge guidance

Read by the local Renovate merge skill. The public renovate-eval action and
skill do not read this file.

## What changes what runs

Clayton's Mac runs the home-manager generation last activated with
`home-manager switch`. The Dagu job `update-nix`
(`config/dagu/dags/update-nix.yaml`) does that every night at midnight from a
fresh worktree of `origin/main`, so a merge reaches the Mac that night at the
latest. An update changes what runs if it changes what home-manager builds:
`flake.nix`, `flake.lock` or `home.nix`, such as the codex and memex inputs.
Deploy and check those after merging, as below, rather than waiting for the
night. Every other update only needs CI, including GitHub Actions, pre-commit
hooks and `flake-versions.yaml`, which only records the versions in
`flake.lock`.

Never update, switch branches in or otherwise touch `~/src/dotfiles`: it is
Clayton's working copy.

## Deploying, after merging

Do what `update-nix` does, from a worktree at the merge commit:

```bash
home-manager switch --flake .#coneill-aarch64-darwin
```

## Checking it works

- `home-manager generations` shows a new current generation from this
  switch.
- The updated program runs and reports the new version, for example
  `codex --version` or `memex --version`.
- Dagu is still running after the switch:
  `launchctl list | grep org.nix-community.home.dagu` shows a PID, and
  `curl -fsS http://localhost:6767/` succeeds. home-manager restarts it only
  when its own launchd settings change.
